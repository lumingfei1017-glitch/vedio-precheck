# 决策：Wan 主路径、TTS 接短镜与无脸镜（2026-11-21）

## 结论

替换路由按「镜头时长 + 人脸/口型 + 违规覆盖率」判定，不再只看人脸。

| 条件 | 路由 |
| --- | --- |
| 口播特写/全身，镜头 ≥2s，违规覆盖 ≥40% | Wan 整镜重生成 |
| 镜头 <2s | TTS 局部换音轨（Wan 最小输出 2s，提交即报错） |
| 画外音、侧身、产品特写 | TTS 局部换音轨，画面不动 |
| 违规只覆盖镜头 <40% | TTS 局部补音，画面不动 |
| 跨镜区间含短镜或无脸镜 | 整段一个 TTS 单元，不拆 |
| 跨镜且全是 ≥2s 口播镜 | 按镜头拆成多个 Wan 单元 |
| 跨镜但文案拆不到每段 | 转人工 |
| 短镜且相邻切点很弱（scene ≤0.40） | 并入相邻镜头补齐到 2–4s，走 Wan |
| 短镜但相邻切点是真实换景 | 不合并，走 TTS |

## 依据

素材：4 条本地素材 / 79 个镜头；违规点：171 条平台审核引文。

- 违规点时长中位 2.13s，均值 3.07s，p90 4.83s；≤5s 占 157/171。
- 镜头时长中位 2.70s，最长 13.07s，没有 ≥15s 的镜头。
- 35%（28/79）的镜头短于 2s，快剪蒙太奇里 0.5–1.0s 的镜头很常见。
- 能对上本地素材的 10 条违规点里，只有 4 条落在单个镜头内，6 条跨 2–4 个镜头。

推论：

1. Wan 单次输出永远 ≤ 参考镜头，`发糊吞字` 的主因是文案密度，不是镜头太长。
2. 成本按调用次数算，不按秒数算。一条视频中位 3 个违规点、约 1.9 镜/点，全走 Wan 约 6 次调用、20 分钟。
3. TTS 只改音轨，不要求对齐硬切，所以跨镜区间对 TTS 是天然支持的；只有 Wan 必须按镜头拆。
4. 30 秒全局参考音在 A/B/C 多段口播素材上必然混音色，TTS 参考音须按镜头、按人取 6–12s。

## 短镜补齐（补齐到 2 秒）

短镜只有两种补法：并入相邻镜头，或者无中生有地加帧。后者要么冻结画面、要么
慢放，都会破坏口播节奏，所以只做前者。

原则：

- 只在违规区间短于 2s、或区间内含 <2s 镜头时触发。
- 向上/向下找相邻**有口播**的镜头，合并后总长落在 2–4s。
- 合并后内部会出现原片切点，Wan 只会输出"一镜到底"，所以必须过画面闸门：
  `ffmpeg scene` 分数 ≤ `MERGE_SCENE_SCORE_MAX`（默认 0.40）才允许合并。
- 合并后按 `4.0–6.5 字/秒` 校验文案密度；偏稀就用被并入镜头的原话补齐，
  偏密就放弃合并、退回 TTS。

实测标定（3 条素材 / 60 个切点）：scene 分数 0.34–0.94，默认阈值下只有 4 个切点
（约 7%）够软可以合并。也就是说多数短镜仍然补不出安全的 2 秒，这批素材里 TTS
依旧是短镜的主通道。阈值可通过 `MERGE_SCENE_SCORE_MAX` 调整，放宽前请先盲看合并结果。

相关配置：`MERGE_SCENE_SCORE_MAX`、`WAN_MERGE_MAX_SECONDS`（默认 4.0）。

## 回贴必须等长

Wan 的 `duration` 官方只接受 **2–30 的整数秒**（或 `-1` 智能时长），而镜头时长几乎
都带小数。之前的 `splice()` 只是把生成片段直接拼回原位，于是：

- 3.503s 的镜头取整成 3 秒生成 → 整条时间轴缩短 0.503s，后面画面与字幕整体前移；
- 合并出的 2.4s 单元 → 缩短 0.4s。

现在 `build_splice_graph()` 会先把生成片段补到槽位长度再拼接：

- 生成短于槽位：`tpad=stop_mode=clone` 冻结末帧、`apad` 补静音；
- 生成长于槽位（≤80ms 容差内）：直接 `trim` / `atrim` 到槽位；
- 两种情况都强制 `trim=0:<槽位>`，保证贴回后总时长不变。

实测：原片 12744ms，2.4s 槽位塞入 2.0s 生成片段，补 0.4s 后输出 12757ms，
偏差 13ms（AAC/帧取整）。

代价是补帧期间画面静止，最长不超过 1 秒，且一定发生在镜头末尾（紧邻下一个切点）。
返回结果里的 `padded_ms` 会给出实际补帧长度，超过 50ms 会写进 `warnings`。

文案预算同时改成按 **Wan 实际生成时长**（整数秒）计算，而不是按参考片段计算，
避免把 3.5 秒的文案量压进 3 秒的生成窗口。
