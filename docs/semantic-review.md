# 语义审核层

## 为什么需要

平台审核经常不是判单个词，而是判一组证据组合。例如：

- “无特效无剪辑，现场给姐妹看一下这个收腹效果”
- “肚子一下就兜进去”
- “压的特别紧实”
- “从肩膀到大腿，整个人的身材都能大变样”

单独看每一句都不一定构成阻断；组合起来就是“真实性背书 + 现场效果演示 + 确定性塑形承诺”。规则快筛会产生多个散点，语义 Agent 负责把它们合并成一条事件。

## 执行顺序

1. ASR 生成逐句字幕和时间码。
2. AP 规则快筛生成高置信候选。
3. 语义 Agent 读取完整口播、时间码和规则候选，输出事件级 `finding + evidence[]`。
4. 被语义事件覆盖的规则 finding 自动去重，保留事件之外的独立规则 finding。
5. 报告和工作台展示证据链；语义失败时回退到规则结果。

## 模型调用

使用 `.env` 中的 `BASE_URL1` 和 `DASHSCOPE_API_KEY`，模型为 `deepseek-v4.1-flash-1017`。请求走 OpenAI 兼容的 `/chat/completions`，启用 `json_object` 响应模式。

## 输出结构

```json
{
  "rule_id": "SEM-APPAREL-EFFECT",
  "title": "现场收腹演示叠加确定性塑形承诺",
  "severity": "blocking",
  "evidence": [
    {"quote": "无特效无剪辑", "start_ms": 23760, "end_ms": 25840},
    {"quote": "现场给姐妹看一下这个收腹效果", "start_ms": 26120, "end_ms": 28320},
    {"quote": "肚子一下就兜进去", "start_ms": 32090, "end_ms": 33290}

  "method": "CUT_BROLL",

  "confidence": 0.97,
  "needs_human": true
}
```

## 验收用例

`v03c8eg10000dbuld1vog65j4akkb5rg`：

- 规则层原来产生 4 条分散命中。
- 语义层合并成 1 条事件，带 6 条证据。
- 另保留 1 条“90斤还是穿北极绒”的适用范围规则，因为它不属于同一事件。

## 可靠性

- 证据必须能在 ASR 原文中逐字找到，否则丢弃。
- 模型返回非法 JSON 时先做控制字符修复，再做一次 JSON 修复重试。
- 语义调用失败不阻断审核，报告记录 `semantic_status=failed` 和错误原因。
- 工作台每条事件都有“误报”按钮，误报写入 `feedback` 表。
