# 局部改口播：人声/BGM 分离与语音块替换方案

> 状态：方案待评审，暂不进入代码执行。等 Wan 3.0 单独验证完成后再整合，统一排期。
> 依据：2026-11-21 本地实测，样本 `参考/测试音频.mp3`（30.15s，44.1kHz 双声道）。

## 0. 一句话结论

本地 Demucs 双轨分离在真实素材上可用：BGM 轨里已经识别不出任何人声，替换窗口的响度可以回到人声水平。因此 A 类（旁白/无正脸）局部改口播可以改成"分离 → 整块重生成 → 只换人声 → 混回原 BGM"，替代现在整轨替换 TTS 的做法。

## 1. 适用范围

| 类型 | 是否需要分离 | 说明 |
|---|---|---|
| B 类 CUT | 不需要 | 视频连音频一起切，BGM 天然连续 |
| A 类 局部改口播 | 需要 | 只替换目标区间人声，BGM/SFX 必须保留 |
| C 类 正脸口型 | 需要 | 等 Wan 3.0 验证后复用本文的混音与复检部分 |

分离只为"改口播"服务，不做成全链路前置，否则纯删段场景会白付一次分离成本。

## 2. 实测数据

| 检查项 | 结果 |
|---|---|
| 人声轨均值 | `-15.2 dB` |
| BGM 轨均值 | `-26.0 dB` |
| BGM 轨 ASR | `ASR_RESPONSE_HAVE_NO_WORDS`，无残留人声 |
| 替换窗口（19.9–23.9s）替换前 | `-24.2 dB`，只剩 BGM |
| 替换窗口替换后 | `-16 ~ -20 dB`，回到人声水平 |
| 窗口前后原声 | `-14 ~ -15.6 dB`，未被改动 |
| 台词校验 | 原句消失、新句就位、前后文完整 |
| 分离耗时（GPU 4070S） | 30s 音频 5.6s，3 分钟素材约 20s |
| 分离耗时（CPU） | 10s 音频 9.4s，约 0.65 倍实时 |

样音：`data/bgm-test/demo/`，其中 `2-bgm-only.mp3` 验分离质量，`7-clip-replace-C.mp3` 验接缝。

### 2.2 Wan 3.0 实测（2026-11-21，同一条 83.7s 竖屏口播素材，共 10 次调用）

| 版本 | 参考 | 输出 | 参考素材 / 提示词 | 结果 |
|---|---|---|---|---|
| A | 6.10s | 6.04s | 仅 `reference_video` | 画面稳、台词准，基频 290.9Hz 明显偏高（原声 238.8Hz） |
| B | 6.10s | 6.04s | + 不同场景音频 | 3.2s 处切到别的场景并新增文字，不可用 |
| C | 6.10s | 6.04s | + 同场景音频 | 画面稳、基频 238.8Hz 与原声一致，开头多一个衬字 |
| D | 6.97s | 7.04s | 整镜替换 31.23–38.17s | 清晰，接缝落在原片硬切，可用 |
| E | 5.50s | 6.04s | 首尾与原句一致 | 串回原句结构，不可用 |
| F | 5.50s | 6.04s | 首尾与原句一致 | 原样复读，与参考音频相关度 0.951 |
| G | 5.50s | 7.04s | 首尾已改写，输出超时长 | 发糊吞字，频谱重心掉到 1453Hz |
| H | 5.50s | 5.04s | 5s / 20 字 | 清晰，但空档被原句碎片"下去，你的身材"填空 |
| I | 5.50s | 5.04s | 5s / 28 字 | 清晰、台词全对、无残留，判定可用 |
| J | 5.50s | 5.04s | 与 G 同文案同提示词，只把 duration 由 7 改 5 | 清晰、ASR 逐字全对，频谱重心 1626Hz |

结论：**I 版与 J 版配方达标**（ASR 全对、与参考音频相关度 0.017 / 0.013、频谱重心 1604 / 1626Hz）。

**时长约束已单变量验证**：G 与 J 使用同一段文案、同一参考镜头、同一提示词、同一参考音频，唯一差别是 `duration` 7 与 5。

| 对比 | duration | 输出 | 结果 |
|---|---|---|---|
| G | 7 | 7.04s（> 参考 5.5s） | 发糊吞字，频谱重心 1453Hz |
| J | 5 | 5.04s（≤ 参考 5.5s） | ASR 逐字正确，频谱重心 1626Hz |

因此"输出时长 ≤ 参考视频时长"从强相关升级为**已验证约束**，可直接作为硬规则执行。

已验证的稳定配方：

1. 整镜替换：切点必须落在原片硬切点（ffmpeg 场景检测），不在镜头中间切；
2. `reference_video` + **同场景** `reference_audio`，跨场景参考会把那个场景带进输出；
3. `duration = floor(参考时长)`，**绝不能超过参考时长**（G/J 单变量对照已验证，超出即发糊）；
4. 文案按 5–5.5 字/秒配，宁可按偏满算，留空档会被原句碎片填空；
5. 新文案首尾不要与原句一致，否则模型会顺着上下文把原句复读回来；
6. `prompt_extend=false`，并明确写"只保留一个镜头、禁止第二场景、禁止新增文字字幕条"；
7. 生成后必须过 ASR 逐字校验 + 音频相关度校验，两项都过才算成功。

## 3. 目标链路

```text
原视频
  ├─ 抽音轨（wav 44.1k 立体声中间态）
  ├─ 人声/BGM 分离 → vocals.wav + no_vocals.wav
  ├─ VAD + ASR 词级时间戳 → 语音块候选（5–12s）
  ├─ 用户确认边界 + 合规文案
  ├─ 克隆音色按整块生成新口播
  ├─ 短语级时长对齐（不整体拉慢）
  ├─ 只替换 vocals 上的目标块，其余原样
  ├─ vocals_新 + no_vocals 混音 → 交叉淡化 → 响度归一
  └─ 回封 mp4 + 字幕替换 + 复检
```

和现在 [edit.py](../app/edit.py) 的差别只有一处：`_mux_tts` 从"整轨替换"变成"分轨局部替换"，其余审核、任务、复检链路不动。

## 4. 边界识别

输入信号四个：VAD 静音点、ASR 词级时间戳、标点停顿、说话人分离。

规则：

- 不切在词中间；
- 不跨说话人；
- 块长优先 5–12s，短于 3s 的块向前后各扩一句，凑够上下文；
- 目标块前后各留 100–200ms handle，用于交叉淡化；
- 第一版自动建议边界，工作台显示波形让用户拖拽确认。

## 5. 时长对齐

不做整块大比例变速，按偏差分档：

| 偏差 | 处理 |
|---|---|
| ≤5% | 直接接受，用 handle 吸收 |
| 5–8% | `atempo` 上限 1.08 |
| >8% | 改文案长度，重新生成 |

整段总时长误差目标 `<200ms`。实测 C 版文案生成 4.128s、窗口 4.08s，偏差 1.2%，用 1.0117 倍速，听感无损。

## 6. 分离 provider

| provider | 依赖 | 成本 | 结论 |
|---|---|---|---|
| 本地 Demucs `htdemucs` | torch + 权重（约 80MB） | 0 | 默认实现，已实测可用 |
| 阿里云 IMS `MusicDemix` | 自有 OSS + RAM AK/SK + 开通 IMS | 约 0.2 元/分钟 | 上量备选，无需自建推理 |
| 火山 AI MediaKit | 火山账号 | 未核 | 有口播场景，可做对比 |

统一封装 `separate_audio(provider) -> (vocals, no_vocals)`，默认 `local_demucs`，配置切换 IMS。

IMS 两个硬限制必须记住：`Input` 只接受 `oss://自己的bucket/object` 或已注册媒资 ID；DashScope 的 `getPolicy` 临时桶属于百炼代管，IMS 读不到，百炼 API Key 也不能直接调 IMS。

## 7. 踩坑清单

| 现象 | 原因 | 对策 |
|---|---|---|
| Demucs 每次卡两分多钟才出结果 | 4.1 版会先探测 HuggingFace 拉模型定义，网络不通时静默重试 5 次 | 设 `HF_HUB_OFFLINE=1`，权重预置到 `TORCH_HOME`，实测从 156s 降到 5.6s |
| 音频文件正常生成，但新配音完全听不见 | `afade` 按时间戳生效，放在 `adelay` 之后，淡出把整段压成静音 | 顺序必须是 `afade → adelay → amix` |
| 混音后整体音量变小 | `amix` 默认 `normalize=1` 会做平均 | 显式写 `normalize=0` |
| `adelay` 只延迟了一个声道 | 立体声需要每个声道一个值 | 写 `adelay=19880\|19880`，按实际声道数生成 |
| 混音后音色发闷或忽大忽小 | TTS 输出 24kHz 单声道，原轨 44.1kHz 立体声 | 混音前统一 `-ar 44100 -ac 2` |
| 接缝处有 20–30ms 偏移 | MP3 编码器有前置延迟 | 中间态一律用 wav，最后一步才转 mp3/aac |
| 脚本看起来"卡死" | 进度输出写满管道后阻塞 | 子进程输出重定向到日志文件，不要直接管道给 Select-Object |
| 只改一句话，前后语气突兀 | 单句没有上下文 | 改成整块 5–12s 重生成，句间用 handle 淡化 |
| 强行拉慢后语速不自然 | 整体 `atempo` 破坏重音和停顿 | 控制在 1.08 以内，超出就改文案 |
| 音色 ID 越建越多 | 每次实验都新建克隆 | 复用已有 voice_id，克隆计费且长期存在 |
| Wan 输出比参考长 0.5s | 多出来的口型没有依据 | 改回原句（E/F 复读） |
| Wan 输出比参考长 1.5s | 只能拉伸含糊带过 | 吐字发糊（G 1453Hz；同文案改 5s 的 J 正常，1626Hz） |
| Wan 文案首尾与原句一致 | 上下文锚定 | 模型把中间原句"填空"回来（F 相关度 0.951） |
| Wan 文案太短、时间留空 | 模型拿参考音填空 | 开头冒出原句碎片（H） |
| Wan 参考音频跨场景 | 画面被参考音带偏 | 中途切镜头（B） |
| Wan 在镜头中间切块 | 原片姿态与生成姿态不接 | 两头跳帧（34.9–41.0 那版） |

## 8. 接口草案

```python
class Stems:
    vocals: Path
    background: Path

def separate_audio(source: Path, work_dir: Path, provider: str = "local_demucs") -> Stems: ...

def propose_voice_blocks(segments: list[Segment], words: list[AsrWord]) -> list[VoiceBlock]: ...

def render_block_replace(
    video: Path,
    stems: Stems,
    block: VoiceBlock,
    new_text: str,
    voice_id: str,
    output: Path,
) -> RenderReport: ...
```

`RenderReport` 至少包含：新旧时长、对齐偏差、atempo 系数、窗口前后响度、ASR 复检台词、是否通过。

## 10. 验收标准

- 新文案 ASR 逐字匹配，原违规句零残留；
- 总时长误差 `<200ms`，块内对齐偏差 `<100ms`；
- 替换窗口响度与前后原声差 `<3dB`；
- BGM 在窗口内可听且连续，主观无"断带"；
- 盲听 5 条，至少 4 条认为"可以直接投"。

Wan 路径额外五项，全过才放行：

- 台词：ASR 与目标文案字面相似度 `≥0.85`，且不含原违规词；
- 复读：与参考镜头音频相关度 `≤0.3`；
- 清晰度：频谱重心不低于参考的 95%，高频占比不低于参考的 0.8 倍；
- 画面：抽帧同一场景，OCR 无新增文字；
- 时长：与参考镜头误差 `<200ms`。

任一项不过，自动落入兜底链，不直接进人工队列。

## 11. Wan 3.0 整合与兜底链

### 11.1 三条修改路径

| 路径 | 适用场景 | 成本 | 口型 |
|---|---|---|---|
| CUT | 违规句可删，或整段镜头可删 | 最低 | 不受影响 |
| 局部 TTS | 侧身/背身/产品特写/画外音，看不到嘴 | 低（秒级） | 不可见，无需对齐 |
| Wan 重生成 | 正脸口播，且这句必须保留 | 高（单次 4–5 分钟） | 重新驱动 |

### 11.2 选路规则

1. 镜头里看不到嘴 → 走局部 TTS，不烧 Wan；
2. 看得到嘴且这句可删 → 走 CUT；
3. 看得到嘴且必须说 → 走 Wan；
4. 一个主张跨多个镜头 → 先按主张聚合，再逐镜头选路，不能只看单个区间。

### 11.3 兜底链（L0 重试 + 三级兜底）

**L0：同配方重试一次**

只对"台词不准/复读"这类随机性错误重试，且换 seed；"发糊/切场景/时长超差"属于参数问题，先按 §2.2 改参数再重试，不要盲目烧调用。重试仍失败才进 L1。

**L1：Wan 失败 → 局部 TTS**

触发条件（任一）：

- 任务 `FAILED` / 超时 40 分钟；
- §10 五项校验任一不过（复读、发糊、切场景、台词不对、时长超差）。

做法：Demucs 分离该镜头 → 克隆音色按目标时长生成新台词 → 只替换 `vocals` → 保留 `no_vocals` → 混音回封。

代价：正脸特写会出现音画不同步，所以 L1 产物统一标记"需人工确认口型"，不自动通过。

**L2：TTS 也不可用 → 删段或换镜头**

触发条件：

- 文案压不进目标区间（改文案后偏差仍 >8%）；
- 没有可用的干净参考音频，克隆不可行；
- L1 成品口型不可接受，且用户选择保合规优先。

做法：CUT 删句，必要时用 B-roll/产品镜头覆盖跳切，字幕同步重排。

**L3：转人工**

触发条件：

- 主张跨镜头且每个镜头都露嘴；
- 多人对话、镜头持续运动；
- 客户要求"必须保口型且不允许不同步"。

做法：输出审核报告、时间轴、建议文案和已尝试路径，交人工处理。

### 11.4 成本与排期

- Wan 单次 6s 片段端到端 4–5 分钟；一条 3 分钟素材改 2–3 处约 10–15 分钟；
- 局部 TTS 秒级；Demucs 分离 GPU 约 15–30 秒/条（3 分钟素材）；
- 批量建议 Wan 并发 2–3 路，超出排队；TTS 与分离走本地并发；
- 兜底链只在失败时触发，正常情况下不产生额外费用。

## 12. 已知风险

- 音乐密集、鼓点重的素材，分离后可能有轻微残留或高频损失，需要抽检；
- 多人对话场景必须先做说话人分离，否则会串音；
- 硬字幕无法靠音频链路解决，仍需 OCR + 区域重绘；
- 克隆音色需演员授权，参考音频要避开原违规句。
