# Spike 报告：说话人分离（2026-11-21）

> 对应计划：[plan-speaker-voice-profile.md](plan-speaker-voice-profile.md) 的 S0。
> 结论：滑窗 + CAM++ 方案可行，单人素材零误判，合成双人素材能分开；真实多人素材样本还不够。

## 1. 环境

- 独立环境 `data/tools/diar-venv`，`--system-site-packages` 复用 CUDA Torch 2.7.1
- `funasr 1.4.27` + `modelscope 1.40.3`，模型 `cam++`（`iic/speech_campplus_sv_zh-cn_16k-common`）
- 模型缓存必须指到项目内：`MODELSCOPE_CACHE=data/tools/ms-cache`（默认路径在用户目录，会被沙箱拒绝）
- 脚本：`data/tools/diar_spike.py`

## 2. 方法

```text
vocals（Demucs）→ 16k 单声道
  → 3s 滑窗、1.5s 步长
  → 每窗 CAM++ embedding
  → 余弦相似度 + 连通分量聚类
  → 按时间重叠投票，把窗口结论映射回 ASR 句子
```

关键教训：**不能用 ASR 句子直接算 embedding**。句子长度在 0.8–3.6s 之间波动，短句 embedding 极不稳定，单人素材会被切成十几个说话人。固定滑窗后问题消失。

## 3. 结果

阈值扫描（窗口 3s / 步长 1.5s，不做去均值）：

| 样本 | 真值 | 0.30 | 0.35 | 0.40 | 0.45 |
|---|---|---|---|---|---|
| 北极绒 83s（单人） | 1 | 1 ✓ | 1 ✓ | 1 ✓ | 1 ✓ |
| 另一条美妆素材（单人） | 1 | 1 ✓ | 1 ✓ | 1 ✓ | 2 ✗ |
| 合成 A+B+A 30s（双人） | 2 | 1 ✗ | 2 ✓ | 2 ✓ | 2 ✓ |

可用区间是 **0.35–0.40**，取 0.40 作为默认值。

合成双人样本：2 类，纯度 0.90（误差来自跨 A/B 边界的滑窗），相似度中位数 0.234、最大值 0.909，块结构清晰。

单人素材按滑窗映射回 42 句 ASR：**全部判为 A，置信度 1.00**，没有误绑。

## 4. 试过但无效的做法

| 做法 | 结果 |
|---|---|
| 用 ASR 句子做 embedding，阈值 0.7 | 单人被判成 15 个说话人 |
| 同上，阈值 0.40 | 单人被判成 4 个说话人 |
| embedding 去均值（`--center`） | 无明显改善，单人在 0.40 仍分裂 |
| 4s 窗口 / 2s 步长 | 比 3s 更差，单人在 0.40 分出 3 类 |

## 7. 真实双人对话样本的声纹测试（v0dc8…pk4fpf6gg，73.96s）

画面确认 39.6–74s 是双人对答：左边米色连衣裙是卖家，右边米色上衣是顾客。ASR 对白结构清晰。

| 方法 | 结果 |
|---|---|
| CAM++，3s 窗口 | 0.30–0.65 全判 1 人；0.70 才分裂但碎片化 |
| CAM++，2s 窗口 | 0.45 分出 2 类，但只把 44.09–45.73 一句判为 B |
| ERes2NetV2，2s 窗口 | 同上，仍只分出那一句 |
| 手切 6 段干净片段做两两相似度 | 卖家内部 0.30、顾客内部 0.44、跨组均值 0.21（最大 0.36） |
| 同上做 k=2 | seller1 单独一类，其余全部合并 |

跨组最大值 0.36 低于顾客内部均值 0.44，说明**同一人内部的相似度波动比人和人之间的差距还大**，任何固定阈值都分不开。

基频倒是能分开：卖家三段 238.8 / 246.2 / 242.4Hz，顾客三段 146.8 / 214.8 / 216.2Hz，相差约 30Hz。

结论：本地声纹 embedding 对"同性别、音色接近、短句、压缩音频"的双人对话不可靠。不能拿它做静默自动归属。

可选改进（按成本排序）：

1. 加基频辅助特征：声纹 embedding  + 句中位 F0 联合聚类，本样本上 F0 能分开。
2. 用轮次结构：短间隔快速交替的对白，本身说明存在多人，先标"疑似多人"再让用户确认。
3. 走云端 `Qwen-Audio-ASR-Filetrans` 的 `diarization_enabled`（异步，需要可访问 URL；现有 `upload_media` 已能拿 `oss://` 临时链接）。
4. 人工兜底：工作台允许手动把某几段绑到 B，这版必须有。

## 8. Wan 重生成双人对白的实测

片段 43.4–48.8s（5.4s，含顾客与卖家各一句），用 Wan 改写对白，跑了两次。

| 版本 | 提示词要点 | ASR 结果 | 与原声相关度 |
|---|---|---|---|
| v1 | "保留两位女性，只把对白换成新台词" | 原台词原样复读 | 0.919 |
| v2 | 开头明确"删除原口播、不要沿用原台词、不要复读原句" | 新对白，逐字正确 | -0.001 |

v2 的对白：

```
0.12-1.56  你看我这肚子是不是有点明显？
1.64-2.28  帮我看看，
2.64-4.00  其实没那么明显。
4.12-5.04  我来看一下。
```

音色保持（句中位 F0）：

| 角色 | 原声 | 重生成 | 偏差 |
|---|---|---|---|
| 顾客 | 214.8Hz | 211.9Hz | -2.9Hz |
| 卖家 | 238.8Hz | 262.3Hz | +23.5Hz |

两个人仍然保持 50Hz 的差距，说明 Wan 没有把双人对白压成同一个声音；顾客几乎完全一致，卖家偏高约 24Hz。

画面抽帧：两人、服装、站位、背景全程一致，没有新增文字或切场景。

结论：**双人对话场景可以不依赖说话人分离，直接用 Wan 重生成**。代价是每次 3.5–4 分钟、需要一次调用，且必须做复读检测（v1 就是复读了）。

## 9. 结论与下一步

可以进入实现，但有三个前提：

1. **阈值要在更多真实双人素材上校准**。目前双人只有一条合成样本（两条不同广告各取 10s 拼接），不是真实的一镜双人。建议补 3–5 条真实多人素材再定 0.40 这个默认值。
2. **边界滑窗要处理**。跨说话人边界的窗口天然混合，映射时要按重叠时长加权（脚本已实现），并给低于 0.7 的置信度打标记，供人工复核。
3. **同性别近似音色的双人对话不能只靠 embedding**。真实样本已验证失败，必须叠加基频特征、轮次启发式或云端 diarization，并保留人工改绑。

性能：模型加载约 8s，3s 窗口单窗推理约 0.05s，83s 素材约 56 个窗口，整体 10s 内完成。
